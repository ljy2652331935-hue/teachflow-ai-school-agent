## Decisions

- Keep the current app acceptable only for anonymous local demo unless the production gate in `SECURITY_REVIEW.md` is completed.
- Treat student free text as untrusted even when it comes from the local prototype.
- Keep school-admin read-only and aggregate-only until a dedicated product decision is made.
- Defer SQLite and real AI integration until CSRF, local cache handling, security headers, and retention policy are addressed.
- Recorded the formal privacy/security gate in `docs/brain/decisions/2026-07-02-formal-privacy-security-gate.md`.
- Recorded school-admin as the third portal in `docs/brain/decisions/2026-07-02-school-admin-third-portal.md`.
- Keep demo data multi-class by default so school-admin views can demonstrate comparison, not only aggregate totals.
- Treat student private memory, class anonymised evidence, and teacher-approved content as separate layers in the long-term AI School Agent architecture.
- Make Governance & Safety a central architecture layer rather than a side note.
- Student Check-in should be framed as `AI 学习关怀助手`, not `AI 心理老师`.
- Teachers should see learning-relevant summaries and support recommendations, not full private student check-in reflections.
- Safety-risk language should be handled by a real school safeguarding workflow before any real deployment; the MVP only flags and explains the boundary.
- Teacher `理解诊断`, `分层干预`, and `学生跟进` are now internal parts of `教学分析`, not separate top-level channels.
- Detailed evidence and student support information should appear in on-demand modals to keep the teacher workspace clean.
- Use Render Blueprint deployment as the first public demo path because the app is a plain Node web service and needs a public URL, not a static-site host.
- Keep public demo accounts passwordless for now, but do not use real student data on the deployed URL.
- Keep the Teams-style message center inside the shared workspace data layer for the MVP, not as a separate real-time chat service.
- Student help requests become teacher-visible messages only when they come from explicit stuck signals or teacher-visible check-in summaries.
- Use one protected Teacher Agent Orchestrator API for teacher briefing and task allocation instead of letting feature APIs call each other directly.

## Problems Encountered

- Historical Chinese text in some docs displayed as mojibake in the Windows shell; affected project-brain docs were rewritten in clean ASCII where practical.
- Current login remains demo-only; it is not production authentication.
- Current JSON persistence and audit events are not production-grade compliance storage.
- Browser `localStorage` can retain demo workspace state and should be cleared on logout/account switch.
- Real AI integration requires a separate provider/data-processing and student-safety review.
- Student Check-in adds a more sensitive learning-support surface; real school use requires approved consent wording, retention policy, and safeguarding escalation roles.
- The in-app browser demo workspace had duplicate sample Teacher Inbox cards, so modal verification used the first visible inbox card after confirming card count.
- Local environment does not have `cloudflared`, `ngrok`, `vercel`, `railway`, or `flyctl` installed, so Codex could prepare deployment files but could not obtain a public cloud URL without user cloud-platform authorization.
- Temporary localhost.run / Pinggy SSH tunnels were unreliable in this environment; local service was restored on port 5175, but a stable public URL still needs Render or another cloud host.
- Teacher message-center sync initially cleared the draft textarea during background refresh; fixed by skipping full channel rerender while a teacher message draft is active.
- Some product pages had accumulated repeated explanatory panels; the first cleanup pass folds secondary details rather than deleting feature surfaces outright.
- Existing local ports `5174` and `5175` were still running older server processes during this turn; tests verified the new route with temporary servers, and a manual server restart is needed for those long-running ports to load `/api/teacher-agent/briefing`.
