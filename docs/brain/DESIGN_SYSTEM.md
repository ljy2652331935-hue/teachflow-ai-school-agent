# TeachFlow UI 设计宪法（DESIGN_SYSTEM.md）

> **任何 AI 会话在修改任何 UI 文件（*.html / *.css / 前端 *.js 的渲染函数）之前，必须先读完本文件。**
> 本文件是硬性约束，不是建议。与本文件冲突的改动，先写 `docs/brain/decisions/` 决策记录，再动手。

适用范围：`outputs/teachflow-school-live/`（老师端、学生端、学校管理端、登录页）。

## 一、硬规则（违反即打回）

1. **指标卡（.metric-card）只放"数字 + 短语"。**
   - `<strong>` 值槽：只允许数字 + 单位（如 `3 类`、`9 人`、`72%`），不超过 6 个字符。
   - `<small>` 注释槽：不超过 14 个字符，超出必须截断。
   - 任何长句、诊断结论、学生原句，一律放进"查看详情"弹层，不进指标卡。

2. **解释性文案默认折叠。**
   - 边界说明、隐私说明、流程解释、AI 能力免责声明，默认收进 `<details>` 折叠区或统一入口，不允许平铺在面板里。
   - 同一段边界/隐私文案在一个端内只允许出现一次（统一位置：侧边栏底部"隐私与边界"折叠区 + 系统设置频道）。

3. **禁止新增浮动窗。**
   - 消息/活动提醒只通过顶栏或侧栏频道按钮上的 `.notice-badge` 数字角标呈现；点击角标所在按钮跳转到消息中心频道。
   - 不允许右下角浮动 dock、不允许展开成浮动面板，不允许带缩放、拖拽、多档尺寸等控件。
   - 新的提醒需求一律走消息中心频道或频道内的 status-pill，不做新浮层。

4. **每屏只有一个主 CTA。**
   - 每个可见屏幕内只允许一个 `.primary-button`；其余动作用 `.secondary-button` / `.plain-button` / `.ghost-button`。
   - 顶栏与频道内容如果同屏出现两个主按钮，删掉一个。

5. **图标只用细线 SVG。**
   - 统一规格：`viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round"`。
   - 禁止：单个汉字当图标、emoji 当图标、实心色块字母图标（品牌 logo "TF" 除外）。

6. **不加新功能的改版就是不加新功能。**
   - "减法专项"类任务里，禁止顺手新增频道、面板、按钮、动画。

## 二、布局与信息架构

- 每个频道页面的骨架顺序固定：顶栏标题 → 指标行（可选，一行以内）→ 一个主工作面板 → 次要面板。
- 信息层级最多两层：面板标题 + 内容。不允许面板里再嵌套多层小标题卡片。
- 列表默认最多显示 3–4 条，更多内容用"查看全部"进弹层或折叠区。
- 空状态必须有：一句话说明 + 数据什么时候会出现。
- 新功能默认挂进现有 7 个老师频道 / 8 个学生频道，不新增顶级入口。

## 三、组件约定

| 组件 | 用途 | 约束 |
| --- | --- | --- |
| `.metric-card` | 数字概览 | 见硬规则 1 |
| `.panel` + `.panel-header` | 所有内容容器 | 标题一行，右侧最多一个 status-pill |
| `.status-pill` | 状态短语 | 不超过 10 个字符，不放句子 |
| `details.compact-disclosure` | 折叠解释文案 | 默认收起 |
| 模态弹层（detail modal） | 长文本、证据、原句 | 长内容唯一去处 |
| `.notice-badge` | 未读提醒数量 | 挂在顶栏/侧栏消息入口；数量为 0 或已在消息频道时隐藏；点击只跳转，不展开 |

## 四、颜色与视觉（Ethereal AI · teachflow-ui.zip）

- **统一皮肤**：`design-tokens.css` + `ethereal-ui.css`（老师/学生/管理/登录共用 token）。
- **主色**：Electric Blue `#2563eb`；背景 `#f8fafc` / 卡片 `#ffffff`。
- **AI 视觉**：渐变 Orb（`.ai-orb`）+ 底部命令栏（`.teacher-command-bar`）。
- **字体**：Inter（标题 200–300，正文 400–500）；禁止再引入 Newsreader / 暖黑 CTA 旧皮肤。
- 改 UI 仍须遵守硬规则 1–3、5–6；新色板以 token 文件为准，页面内禁止硬编码第二套色。

## 五、修改流程

1. 动 UI 前读完本文件。
2. 改动说明里写清触碰了哪几条规则。
3. 想违反任何一条：先在 `docs/brain/decisions/` 写决策记录，说明理由和替代方案。
4. 完成后按 `AGENTS.md` 要求更新当天 devlog。
